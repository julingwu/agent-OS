# AgentOS V4.3.0 发版说明 · 动态财务预算引擎

发布日：2026-10-21 ｜ 基线：`main@e2a3bc8`（V4.2.0）

## 一句话

预算从「一刀切 2 万」变成「按阶段估价 + 项目池 + 花到 80% 要钱」：小活不浪费、大单不卡死、真跑飞了也有兜底。

## 战役一 · 财务预估算（阶段额度 = 估价 × 弹性系数）

- DAG 规划完成后，财务 Agent（`app/finance.py::estimate`）逐阶段给 `base_estimate`：
  按阶段类型（retrieve 30k / analyze 12k / author 12k / review 6k / deliver 0.8k / implement 30k …）、
  角色加权、需求复杂度（短需求 ×0.9、长需求 ×1.15、紧急流 ×1.2）算出基础预估，
  再乘**弹性系数**（默认 1.5 = 自动附 50% 试错缓冲）得到该阶段**初始额度**。
- **项目总预算池 = 各阶段初始额度之和**；超过全局上限（默认 100 万）时等比压缩，
  并把压缩标记写进预算池（界面显示「已压到全局上限」）。
- 群里的《作战计划》直接带出「项目预算池 · 93,000 tokens（弹性系数 1.5，含 50% 试错缓冲）」
  和逐阶段的「基础预估 / 初始额度」表；CEO 台立项消息也带上预算池数字。

## 战役二 · 池化与弹性追加（核心）

- **废除固定 2 万**：流程阶段不再读 `M0_FLOW_STAGE_BUDGET`，改为读预算池里的阶段额度
  （老项目没有预算表时仍回退旧参数，保证历史项目能跑完）。
- **80% 暂停**：`runner_acp` 在每次 usage 回报时比对「本次可花额度 × 0.8」，
  到线立即 `client.cancel()`，run 记 `budget_pause`（exit 5），阶段转 `awaiting_budget`，
  项目转 `paused`，同时生成一张**追加预算审批卡**（同一阶段不会重复刷卡）。
- **批准即划拨**：老板批准后从池子**未花余额**划给该阶段（`grant = min(申请, 剩余)`），
  阶段额度上调、`topups+1`，项目回到 `active`；「批准并继续」会从断点重跑未完成阶段。
- **池子见底强制停摆**：未花余额 ≤ 0 时审批卡直接落 `exhausted`，项目 `halted`，
  企微推送「项目预算池已见底，项目强制停摆」，且 `_flow_execute` 之后再开工直接抛 `BudgetHalt`。
- 预算相关状态不会误判成「失败」：`Pipeline.run_project` 单独捕获 `BudgetPause/BudgetHalt`，
  阶段落 `awaiting_budget`、项目落 `paused`，不会打上红色失败mark。

## 战役三 · 前端财务展示

- **项目卡**：预算条（池 / 已花 / 剩余 / 弹性 / 80% 暂停线）+ 每阶段消耗 chip（≥80% 变红，
  待批预算高亮）+ 「追加预算审批」卡（批准并继续 / 驳回）。
- **用量与费用**：新增「项目预算池（动态财务引擎）」表（池 / 已花 / 剩余 / 状态）与
  「待批追加预算」列表，可原地批准或驳回。
- **设置页**：原来的「单阶段固定预算」换成 **默认弹性系数（1.5）** 与
  **项目全局最高预算（100 万）**，配 80% 暂停线说明；保存立即影响新项目。

## 数据表（新增，均为幂等建表）

| 表 | 用途 |
|---|---|
| `project_budgets` | 每个项目的池子总量、已花、弹性系数、全局上限、状态（active/paused/halted） |
| `stage_budgets` | 每阶段基础预估、缓冲、额度、已花、追加次数、状态 |
| `budget_approvals` | 追加申请：申请额、批准额、状态、申请/审批人 |
| `budget_events` | 估算 / 暂停 / 追加 / 批准 / 驳回 / 停摆 的全量流水 |

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/ui/projects/{pid}/budget` | 项目预算池 + 逐阶段额度/已花 |

## 已知边界

1. 估价是**规则表 + 复杂度系数**，不是模型估价：好处是 0 token、可解释、可测；
   代价是极端任务（超长报告、深网检索）仍可能一次撞到 80% 线，靠追加解决。
2. 80% 判定基于 `usage_update` 的累计值，粒度取决于底座回报频率；超过额度 100%
   的老硬顶仍然保留（当作最后一道闸门）。
3. 追加只从**未花余额**划拨，不允许超出池子；要放大池子只能改弹性系数/上限后新建项目，
   或者走追加（会抬高池内占用）。
4. 「批准并继续」是重跑未完成阶段（不续会话），会重新消耗前一段已花的 token；
   若需要会话级续跑，单独排期。
5. 预算审批目前不做按角色细分权限：能登录工作台并打开审批区的账号即可批（单租户 HQ 部署）。
