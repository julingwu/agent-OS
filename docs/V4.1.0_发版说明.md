# AgentOS V4.1.0 发版说明 · 智能调度与全景执行可视化

发布日：2026-10-20 ｜ 基线：`main@192a8e9`（V4.0.0 冻结版）

## 一句话

流程从「写死九段」变成「按需求规划 DAG」，执行过程能在界面上逐条看见，失败会自己给出中文诊断——一句话需求进来，出去的是一条可追溯的作战链路。

## 四大战役

| 战役 | 交付 | 关键文件 |
|---|---|---|
| 一 · 阶段全景与实时执行流 | 阶段全景可点开：交付物 / 闸门 / 黑板 / 历史 Run+Trace / 审计；进行中阶段内嵌 SSE，逐条推 thinking / tool_call / tool_result / model | `app/ui/api.py`（`/ui/runs/{id}/live-stream`、`/ui/projects/{p}/stages/{k}`）、`web/src/ProjectFlow.jsx` |
| 二 · 动态流程编排（DAG） | `flow_templates` 四套模板（软件交付 8 步 / 分析报告 5 步 / 调研 6 步 / 紧急 4 步）；CEO 接单后先规划（关键词 → 模型 → 兜底），项目阶段按 DAG 落库 | `app/flows.py`、`app/pipeline.py`、`app/ui/dispatcher.py` |
| 三 · 协作群与分工链路 | 规划完自动建群，只拉规划命中的角色；群内发「作战计划」（阶段/角色/依赖/闸门）；每段产出写黑板 `project_artifacts`，PM 收尾汇总；支持同角色多人 + PM 指定执行人 | `dispatcher.open_group/plan_message/assign`、`flows.blackboard/pm_summary` |
| 四 · 失败可视化与诊断 | 阶段失败红色 ✕ + 脉冲动画；点开即见失败诊断（中文根因 + 最多 3 条修复建议 + 一键重试），失败 Run 可直达 | `flows.diagnose`、`/ui/runs/{id}/diagnosis`、`web/src/ProjectFlow.jsx` |

## 新增接口

- `GET /ui/flow-templates` —— 四套流程模板
- `GET /ui/projects/{pid}/stages/{key}` —— 阶段详情（交付物/闸门/黑板/Run/审计）
- `GET /ui/projects/{pid}/stages/{key}/files/{delivery_id}` —— 阶段交付物下载
- `POST /ui/projects/{pid}/stages/{key}/assign` —— PM 指定阶段执行人
- `GET /ui/runs/{run_id}/live-stream` —— SSE 实时执行流（`?t=` 带票据，desktop/browser 通用）
- `GET /ui/runs/{run_id}/diagnosis` —— 失败诊断（规则优先，模型补充，结果落 `run_diagnoses` 缓存）

## 已知边界

1. **分析/调研流的每个阶段都会真跑一次 ACP**（`M0_FLOW_EXEC=1` 默认开）。一个 5 段项目≈5 次模型调用；要省钱可置 `M0_FLOW_EXEC=0`（退回模板文档，链路仍可跑通，但没有真实思考流）。
2. SSE 用 `?t=<会话票据>` 传凭据（与预览票据同一入口）；会话票据会出现在访问日志里，内网自用可接受，公网部署建议让网关脱敏 query。
3. 旧项目（V3.x 的九段流）保持原样可跑，`flow_id` 为空；新项目才走模板。
4. 诊断的模型补充仅在 `task_runs.state != succeeded` 时调用一次，失败则退回规则结论，不会卡住界面。
5. 企微群通知仍只覆盖「9/9 闭环 / 红线拦截」两类事件；流程节点的完成不单独推送。
