# Agent OS v1.1 发布说明

**版本**：v1.1.0 ｜ **日期**：2026-10-19 ｜ **基线**：v1.0.0（2026-10-18 封版）
**引擎**：DSH (ACP) + FastAPI + SQLite ｜ **外壳**：Tauri 2 / React 18

> 一句话：v1.0 让系统「能干活」，v1.1 让它「记得住、查得到、管得动、自己会起来」。

---

## 一、模块 A：注入灵魂（记忆 / 上下文 / 查库）

| 能力 | 状态 | 实现位置 | 证据 |
|---|---|---|---|
| 全局偏好记忆 | **已实现** | `app/ui/intel.py`、`user_preferences` 表 | 说「以后叫我老板」→ 写库并回「好的，以后就叫您老板。」 |
| 偏好注入每次 Prompt | **已实现** | `pref_block()` 拼进 `classify` 的 system 与任务 prompt | 接着聊「今天天气不错」→「是呀**老板**，秋高气爽的…」 |
| 群聊最近 10 条上下文 | **已实现** | `history_block()` + `build_task_prompt()` | 任务 prompt 里出现「【群里最近的对话】」段 |
| 查库工具（组织/任务/预算） | **已实现（服务端执行后注入）** | `intel.lookup()` | 「我的秘书呢」→「老板，我这边看到群里只有小测、小码和我…」（真实姓名，不是瞎猜） |
| 闲聊 vs 派活 | **已实现** | `app/octo/intent.py::classify` | 闲聊不建任务；派活才拆解建任务 |

**取舍**：ACP 侧只接受一段文本，不能让模型真正 function-call，所以「工具」是**服务端先查库、把事实写进 prompt**。
效果等价（模型只负责措辞，不许编造），代价是每次闲聊多一次 ~200 tokens 的查询，可接受。

## 二、模块 B：企业级管理

| 能力 | 状态 | 说明 |
|---|---|---|
| 群聊「⋯」：邀请 / 移出 / 退出解散 | **已实现** | `chat_members.state='removed'` 软删除；群主退出即解散并改名「（已解散）」 |
| 员工详情：编辑人设 / 模型 / API Key | **已实现** | `PATCH /ui/employees/{id}`，API Key 只写不回显 |

| 左侧底部：设置 + 账号 | **已实现** | 设置含模型全局配置/主题/定时任务/知识库；账号含身份、角色、偏好、改密钥 |

`agent_fired` 的 payload 会带上 `budgets_released` 与 `runs_stopped` 两个数字。

## 六、遇到的坑与解法

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | `classify` 新增参数后 f-string 被换行截断 | `SyntaxError: unterminated f-string` | 改用 `NL = chr(10)` 拼接，避免反斜杠转义在多层工具链里被吃掉 |
| 2 | 新路由 `/ui/about` 一律 401 | Cookie 参数没写 `Cookie(...)`，被当成 query 参数；Bearer 也没读 | `_ident` 显式 `Cookie(default=None)` + `Header(default=None)` |
| 3 | 换了新路由但服务还是旧的 | 端口被上一进程占着，新进程没绑上 | 先 kill 监听 PID 再起；`/ui/me` 通而 `/ui/about` 不通就是典型症状 |
| 4 | 审计插入失败 | `NOT NULL constraint failed: ai_audit_logs.legal_entity_id` | 管理面事件统一挂 `LE-GROUP-HQ`，不再传 None |
| 5 | m11 测试单跑绿、全量红 | 会话票据在 import 时签名，别的测试改了签名密钥 | token 改成调用时计算（`tok()`） |
| 6 | 偏好正则误伤 | 「叫我看看这个」被记成 `boss_title=看看这个` | 只接受 1–6 字且不含动词的称呼 |
| 7 | Tauri 打包 `os error 5` | 旧版 exe 在运行 / NSIS 半截解压 | 先 `Stop-Process`，再删 `%LOCALAPPDATA%\tauri\nsis-3.13` |
| 8 | 旧 dist 与新 dist 打架 | 桌面端白屏，控制台 `MIME text/html` | Vite `base: "./"`，一份产物两处可用 |

## 七、测试与覆盖率

| 类别 | 数量 | 说明 |
|---|---|---|
| 单元 / 集成（pytest） | **105 passed** | v1.0 的 96 条 + v1.1 新增 9 条（`tests/test_m11_core.py`） |
| E2E（Playwright） | **11 步全过** | 登录 → 会话列表(4) → 群聊 → 闲聊不建任务 → 验收卡展开 → 员工面板 → 文件库(55 个产物) → 设置 → 帮助 → 关于 → 群聊菜单 → 主题(light) |
| 真实模型验收（人工场景） | **3 句通过** | 「以后叫我老板」→「今天天气不错」（叫对了老板）→「我的秘书呢」（答出真实同事名） |

**覆盖率（coverage 实测，2026-10-19）**：`app/` 全量 **67%**（4412 行，未覆盖 1446 行）。

| 模块 | 覆盖率 | 说明 |
|---|---|---|
| `app/ui/intel.py` | 80% | 偏好/上下文/查库是新逻辑，测得最细 |
| `app/ui/admin.py` | 50% | 群/员工/文件/知识库，主要路径覆盖 |
| `app/ui/ops.py` | 58% | 告警与定时任务 |
| `app/ui/api.py` | 25% | 对话编排（_run_turn）跑真实模型，单测刻意不碰 |
| 旧底座（state_machine/relay/policy/tenant） | 82–97% | v1.0 遗产，稳定 |

低的那几块不是没测，而是**走 E2E 与真机任务**验证（发消息、跑 ACP、出卡片），
在 pytest 里重跑一遍既慢又要花 token。

### 如何复跑

```powershell
# 单测
$env:PYTHONIOENCODING='utf-8'; .venv\Scripts\python.exe -m pytest -q

# E2E（需 8077 在跑）
.venv\Scripts\python.exe tools\e2e_console.py            # headless
.venv\Scripts\python.exe tools\e2e_console.py --headed    # 看得见

# 覆盖率
.venv\Scripts\python.exe -m coverage run -m pytest -q
.venv\Scripts\python.exe -m coverage report --include="app/*"
```
