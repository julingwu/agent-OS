# Grok Bot 功能对照表（Feature Parity）

> 基准：Grok Bot 官方文档（x.ai/docs/grok-bot，2026-10 抓取）+ 截图实测
> 判定口径：**"实现" = 有等价能力且能在我们体系里跑通；"延后" = 明确排期但不是砍掉；"不做" = 有理由的取舍。**

---

## 1. Bots（Bot 管理）

| Grok Bot | 我们 v1 | 判定 |
|---|---|---|
| Bot = 有名字/职责/独立会话/持续上下文 | `bots` 表 + `persona` + 独立 session | ✅ 实现 |
| 在聊天里创建（New chat → Create new Bot） | 同：对话式创建，主 Bot 引导 | ✅ 实现 |
| 改名/头像/标签 | `PATCH /v1/bots/{id}` + 详情页 | ✅ 实现 |
| 详情页：模型、记忆、用量 | 详情页聚合：模型可切换、记忆管理、token/费用 | ✅ 实现 |
| 置顶/隐藏/分组 | 侧栏 pin/hide/sections | ✅ 实现 |
| 复制 Bot（不含历史/记忆） | `duplicate` | ✅ 实现 |
| 分享模板 / Marketplace | — | ⏸ 延后（自用无意义，等多人再说） |
| 删除 Bot | 软删 + 保留审计 | ✅ 实现 |
| 团队 Bot（Team Bot） | — | ❌ 不做（单用户） |

## 2. 聊天

| Grok Bot | 我们 v1 | 判定 |
|---|---|---|
| 发消息/附件/粘贴图片链接 | `POST messages` + 上传 | ✅ 实现 |
| 附件：6 个/次，文档图片音频 25MB，视频 200MB | 同 | ✅ 实现 |
| 语音输入（听写进输入框） | exe 录音 → ASR → 回填可编辑 | ✅ 实现 |
| 语音备忘（Bot 回语音） | TTS + 播放条 + 转写 | ✅ 实现 |
| **实时语音通话** | — | ⏸ 延后（WebRTC 全套 + 流式 ASR/TTS，2–3 周，且 5Mbps 体验一般） |
| `/` 引用技能、`@` 提 Bot/群/例行任务/应用 | 同 | ✅ 实现 |
| 回复某条消息、表情、线程 | reply_to + reactions + threads | ✅ 实现 |
| 工作中追加指令、直接说"停" | 消息优先级 + `POST /stop` | ✅ 实现 |
| 草稿审阅（邮件/Slack，可编辑后发送/丢弃） | `draft.created` 卡片 + 发送需批准 | ✅ 实现（先做邮件/企微） |
| 群聊 2–6 个 Bot、@、@everyone | sessions 多成员 + 路由 | ✅ 实现 |
| Bot 之间异步交接（handoff） | `handoffs` 三事件 + 环路/预算闸 | ✅ 实现 |
| 群聊里不出现审批/密钥/草稿 | 路由规则：敏感卡片只进单聊 | ✅ 实现 |
| 搜索/命令面板（Cmd+K）、快捷键 | 全局搜索 + 快捷键表 | ✅ 实现 |
| Pages（Bot 生成的可分享报告/看板） | 生成 HTML artifact + 内嵌预览 | ✅ 部分（不做公网分享） |
| Cloud Agents（把编码活外包给云端 agent） | — | ❌ 不做（我们本身就是） |
| X 搜索/读取 | — | ❌ 不做（无账号体系依赖） |

## 3. 电脑（Computer）

| Grok Bot | 我们 v1 | 判定 |
|---|---|---|
| 每账号一台持久云电脑，所有 Bot 共享 | **一个容器** + 共享 `/workspace` + 每 Bot 独立 display/profile | ✅ 实现（登录态共享见下） |
| 每个 Bot 一块屏，可并行 | 每 Bot 一个 Xvfb display + chromium | ✅ 实现 |
| 右侧面板电脑预览（点击/输入/状态） | 截图流 2fps 自适应 | ✅ 实现 |
| 关掉 App 继续跑 | 容器常驻 + 进程 supervisor | ✅ 实现 |
| 敏感步骤接管（密码/2FA/验证码/支付） | `needs_human` + 截图 + KasmVNC 接管 | ✅ 实现 |
| 登录一次，浏览器会话持久 | 持久 chrome profile + cookie 同步服务 | ✅ 实现 |
| Connect apps（OAuth 应用，token 不落到电脑） | MCP 服务器（`app/mcp.py` 已有一半）+ 服务端持 token | ✅ 实现 |
| `/workspace` 共享文件 | 容器卷 `/workspace` | ✅ 实现 |
| 更新/恢复/重置电脑（保留文件与登录态） | `computer/reset`：重建容器、挂回卷 | ✅ 实现 |
| **本地电脑能力**（Ask every time / Always allow / Never） | exe 本地桥 + 三档策略 | ✅ 实现（这是"exe 不是瘦客户端"的核心） |
| 机密值请求（掩码、不进模型） | `/v1/secrets` + 掩码输入 | ✅ 实现 |
| 网络策略/出站白名单 | nginx/iptables + 域名白名单 | ✅ 实现 |

## 8. 从 DS-Bot 借什么（它是 DSH 插件，同源，Apache 2.0）

| DS-Bot 的做法 | 借不借 | 说明 |
|---|---|---|
| 主 Bot（Chief）管理其他 Bot 和群 | ✅ 借 | 对应我们的 planner/首席 Bot |
| 群聊有 admin，默认由 admin 应答，@ 直接点名 | ✅ 借 | 直接做成路由规则 |
| Bot 之间用 @ 交接，接收方自己干、群里持续汇报 | ✅ 借 | 与 handoff 三事件对齐 |
| 群里每个成员一个独立 session（Hermes 模式） | ✅ 借 | 避免上下文串味 |
| 群聊有独立记忆，不外泄 | ✅ 借 | 群 session 级记忆作用域 |
| 能力库（MCP servers / skills / packs 共享） | ✅ 借 | 对应"连接应用 + 技能库" |
| 记忆用 Markdown 存储（AgentMemoryRepo 格式） | ✅ 借 | 人可读、可 diff、可导出 |
| 长对话压缩时保留用户消息 + 摘要（Codex 的 checkpoint） | ✅ 借 | 压缩策略直接抄 |
| 消息锚点/聊天搜索用 SQLite FTS 索引 | ✅ 借 | 我们已有 SQLite，零成本 |
| 桌面应用自带运行时、自动更新 | ✅ 借 | Tauri updater |
| **本地优先、所有数据留本机** | ❌ 不借 | 我们要"关掉电脑还在跑"，必须云端为主 |
| **没有云电脑/进程/例行任务/接管** | ❌ 不借 | 这正是我们要补的 |

## 9. v1 明确不做（有理由，不是遗漏）

| 不做 | 理由 | 什么时候可能做 |
|---|---|---|
| 实时语音通话 | 需要 WebRTC + 流式 ASR/TTS + 打断处理，2–3 周；5Mbps 下体验打折 | v2 |
| 原生移动 App | 企微已覆盖 80% 场景；Tauri 2 可复用前端，但上架/签名/推送要 1–2 周 | v1.1 |
| Bot 模板分享 / Marketplace | 单用户无意义 | 多人版本 |
| Team Bot / 团队策略 / 连接器策略 | 单用户 | 多人版本 |
| Cloud Agents / X 集成 | 依赖外部平台账号体系 | 需要时 |
| 示范录制技能 | v1 用"事件流生成技能"覆盖核心场景 | v1.1 |
| Pages 公网分享 | 自用不需要；内嵌预览已够 | 需要时 |
